# Home Assistant Golden Payloads

This document pins representative Home Assistant dry-run payloads generated by
EdgeHome Harness after model output has passed Rust validation, device
resolution, capability checks, and policy gates.

These are not model outputs. MiniCPM never emits `entity_id`, service paths,
tokens, URLs, or Home Assistant payloads. Those values are produced by the
registry and Home Assistant adapter after the internal command is verified.

## Boundary

```text
Chinese user input
  -> backend-neutral ModelCandidate
  -> NormalizedCommand
  -> GateEngine / GatedCommand
  -> Dry-run ExecutionPlan
  -> HomeAssistantAdapter dry-run payload
```

Real Home Assistant execution remains disabled by default. Dry-run payload
generation does not require a token and does not call a real Home Assistant
instance.

## Registry Source

Example registry records:

```yaml
- device_id: hallway_light
  aliases: ["走廊灯"]
  room: hallway
  device_type: light
  backend: home_assistant
  backend_entity_id: light.hallway
  risk_level: low

- device_id: bedroom_air_conditioner
  aliases: ["卧室空调"]
  room: bedroom
  device_type: air_conditioner
  backend: home_assistant
  backend_entity_id: climate.bedroom_ac
  risk_level: medium
```

The `backend_entity_id` field is registry-owned. It is not part of the MiniCPM
prompt contract.

## Light Turn On

User input:

```text
打开走廊灯
```

Verified internal command:

```json
{
  "device_id": "hallway_light",
  "device_type": "light",
  "action": "turn_on",
  "policy": "allow"
}
```

Home Assistant dry-run payload:

```json
{
  "backend": "home_assistant",
  "device_id": "hallway_light",
  "entity_id": "light.hallway",
  "room": "hallway",
  "device_type": "light",
  "action": "turn_on",
  "service": "light.turn_on",
  "service_path": "/api/services/light/turn_on",
  "payload": {
    "entity_id": "light.hallway"
  },
  "condition": {
    "time_after": null
  }
}
```

```json
  "service_path": "/api/services/light/turn_on",

    "entity_id": "light.hallway",

  "condition": {
    "time_after": "22:00"
```
```json
  }
}
```

## Fail-Closed Examples

The Home Assistant adapter must fail closed for:

```text
missing route
invalid entity_id
unsupported action/domain pair
missing token during real execute
non-2xx Home Assistant response
real execute when execute_enabled = false
```

Relevant tests:

```powershell
cargo test -p edgehome-executor home_assistant
cargo test -p edgehome-executor dry_run_planner_translates_home_assistant
```

## Claim Boundary

This document demonstrates the Home Assistant gateway boundary with pinned
payload shapes. It does not claim full Home Assistant production coverage,
replacement of Home Assistant, or real-device execution by default.
