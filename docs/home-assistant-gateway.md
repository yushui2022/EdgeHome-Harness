# Home Assistant Gateway Boundary

Home Assistant support is a gateway boundary in front of Home Assistant, not a
replacement for Home Assistant.

```text
MiniCPM candidate JSON
  -> Rust validation / normalization
  -> DeviceRegistry entity_id
  -> Gated ExecutionPlan
  -> Home Assistant service call
```

MiniCPM never sees:

```text
Home Assistant token
entity_id
service path
base URL
private network route
execute switch
```

## Config

Example:

```yaml
base_url: http://homeassistant.local:8123
token_env: EDGEHOME_HA_TOKEN
token_file:
request_timeout_ms: 8000
execute_enabled: false
verify_state_after_execute: true
```

`execute_enabled` must stay false in public examples. Enable it only in private
local config after dry-run, gate, confirmation, rate-limit, and idempotency
checks are in place.

## Registry Route

Example:

```yaml
devices:
  - device_id: hallway_light
    aliases: ["hallway light"]
    room: hallway
    device_type: light
    backend: home_assistant
    backend_entity_id: light.hallway
    risk_level: low
```

The `entity_id` comes from the trusted registry. It is not model output.

## Gateway Readiness

The executor exposes route validation so bad entity IDs can fail before runtime:

```text
HomeAssistantExecutor::validate_routes(devices)
```

The current checks reject entity IDs with path separators, whitespace, control
characters, missing domain, or missing object ID.

## Dry-Run

Dry-run does not require a token and does not call Home Assistant. It returns a
reviewable service-call payload:

```json
{
  "backend": "home_assistant",
  "device_id": "hallway_light",
  "entity_id": "light.hallway",
  "service": "light.turn_on",
  "service_path": "/api/services/light/turn_on",
  "payload": {
    "entity_id": "light.hallway"
  }
}
```

## Real Execute

Real execution requires all of:

```text
execute_enabled = true
token available through token_env or token_file
dry-run plan generated
gate accepted
policy not denied
user confirmation when required by risk
rate limit and idempotency checks passed
```

When `verify_state_after_execute = true`, the executor fetches entity state
after the service call and includes the parsed post-state in the executor
response. If the state fetch fails, execution returns an error instead of
pretending verification succeeded.

## Failure Behavior

The Home Assistant gateway fails closed for:

```text
missing route
invalid entity_id
unsupported action/domain pair
missing token during real execute
unsupported base URL
non-2xx Home Assistant response
post-state fetch failure when verification is enabled
execute_enabled = false
policy denied
```

CLI shape:

```powershell
cargo run -q -p edgehome-cli -- --db-path edgehome-demo.sqlite execute <trace_id> --confirm --backend-config private/home_assistant.yaml
```

The CLI executes only a previously recorded dry-run trace. It does not execute
fresh natural-language input directly.

## Tests

Relevant tests:

```powershell
cargo test -p edgehome-executor home_assistant
cargo test -p edgehome-executor dry_run_planner_translates_home_assistant
```

## Claim Boundary

Allowed public claim:

```text
Home Assistant gateway boundary implemented with dry-run payloads, explicit
opt-in REST execution, route validation, token isolation, and optional post-state
fetch.
```

Do not claim:

```text
Home Assistant replacement
Full production HA coverage
Default real device execution
HA token or entity_id generated by MiniCPM
```
